# Таски ментора — nmt.in.ua

**Репозиторій:** `tony-kobs/nmt.in.ua`  
**Гілка:** `dev` → `feat/...` → PR у `dev`  
**Правила:** логіка в `src/modules/*`, UI в `src/components/*`, тонкі сторінки в `src/app/*`. Креденшли лише в `.env.local`, не в git.

**Залежності модулів:** `2 (контент) → 3 (тест) → 4 (рекомендації)`; модуль `1` збирає UI навколо них.

### Таска 1.3 — UI «Навчальні сесії» (`/sessions`)

### Таска 1.5 — Лід `/`: старт → тренажер
**Що:** після успішного `startTopicTest` перехід у UI тренажера (модуль 3), не лише показ `sessionId`.

## Модуль 2. Імпорт (CSV, JSON → БД)

Код імпорту вже є (`src/modules/content-import/*`, `POST /api/import`). Зараз — ops/QA і опційний UI.

### Таска 2.1 — Підключити БД і ключ імпорту локально
**Що:** `.env.local` з `.env.example`: `DB_*` + `CONTENT_IMPORT_API_KEY`.  
**Acceptance:** немає `Missing DB_HOST`; `POST /api/import` без ключа → `401`.

### Таска 2.2 — Smoke-тест імпорту в живу БД
**Що:** маленький CSV або JSON через `curl` (README); перевірити `themes` / `quiz_tasks` у phpMyAdmin; негативні кейси (битий `right_answer_n`, без Bearer).  
**Acceptance:** успішний імпорт → рядки в БД; помилки → `400`/`401` без витоку секретів.

### Таска 2.3 — Прод: ліміт тіла запиту
**Що:** на хостингу `MAX_BODY_BYTES=8388608` (див. `.env.example` / README).  
**Acceptance:** реальний імпорт не відсікається `413` на `server.js` до Next.

### Таска 2.4 (опційно) — UI імпорту
**Що:** блок у `/settings` або `/admin/import` → лише виклик існуючого `POST /api/import`.  
**Acceptance:** адмін може завантажити файл без `curl`; без ключа/ролі — відмова.

## Модуль 3. Тест + інтерактивні тренажери

Вже є: `TopicTestStart`, `startTopicTest` (1× `task_sessions` + 10× `tasks2session`). Немає: проходження, `checkAnswer`, `finishTrainerSession`.

### Таска 3.1 — Дістати завдання сесії з БД
**Що:** `getSessionTasks(sessionId)` у `src/modules/testing/` (JOIN `tasks2session` + `quiz_tasks`). Не віддавати клієнту `right_answer_n` (і краще `comments`) до перевірки/фінішу.  
**Acceptance:** 10 завдань з текстом і 4 варіантами; unit-тест.

### Таска 3.2 — UI тренажера
**Що:** `src/components/testing/` — питання, 4 відповіді, прогрес 1/10; після старту — `/session/[id]` або інлайн на `/`.  
**Acceptance:** видно реальні завдання з БД; можна клікати варіанти.

### Таска 3.3 — `checkAnswer` (сервер)
**Що:** порівняти з `right_answer_n`, оновити `tasks2session.status` (`0` / `1` / `-1` — узгодити), Server Action.  
**Acceptance:** статус у БД коректний; відповідь не світиться в Network до відповіді сервера; тести.

### Таска 3.4 — `finishTrainerSession` + підсумок
**Що:** вірно/всього/%/час → `task_sessions`; UI підсумку + лінки на `/results`, `/sessions`.  
**Acceptance:** сесія «виконана», % збігається; повторний фініш ідемпотентний або заборонений.

### Таска 3.5 — Таймер / час
**Що:** час сесії (і бажано на питання) → `task_sessions.time`; узгодити `start_time` з ментором.  
**Acceptance:** у завершеній сесії `time > 0`.

### Таска 3.6 — Теми з `themes`, не хардкод
**Що:** селект у `TopicTestStart` з БД.  
**Acceptance:** нові теми після імпорту з’являються без хардкоду.

### Таска 3.7 — `/sessions` з даними БД
**Що:** список сесій користувача з `task_sessions` (+ назва теми); статуси; продовжити/старт.  
**Acceptance:** після тесту сесія в таблиці з % і часом.

### Таска 3.8 (пізніше) — Симулятор НМТ
**Що:** `/simulator` + `startNmtSimulator` (окремий `session_type`, таймер).  
**Acceptance:** симулятор стартує окремо від короткого тесту за темою.

### Таска 3.9 (пізніше) — Задачник
**Що:** `/problems` — банк з `quiz_tasks`, перевірка через той самий серверний flow.  
**Acceptance:** фільтр по темі, відкриття завдання, перевірка відповіді.

## Модуль 4. Рекомендаційна система

Залежність: якісні дані після `finishTrainerSession` (3.3–3.4). Евристики/UI можна почати на mock.

### Таска 4.1 — Агрегат статистики по темах
**Що:** `getStudentTopicStats(userId)` → `StudentResultSnapshot` (`topicScores`: %, середній час).  
**Acceptance:** коректний масив для тестового user; теми без сесій не ламають відповідь; unit-тест.

### Таска 4.2 — `recommendNextActions` (евристики MVP)
**Що:** правила в `src/modules/recommendations/`:
- `% < 40` → повторний тест теми (`topic-test`)
- `40–69` / повільно → `problems` / матеріали
- усі ≥ 70 → `simulator` або наступна тема
- стабільно низько → `consultation`

**Acceptance:** стабільний список на фіксованому snapshot + тести; порожній snapshot → `[]` або CTA «Пройти перший тест».

### Таска 4.3 — Тригер після фінішу тесту
**Що:** у `finishTrainerSession` → stats → `recommendNextActions`; блок «Що далі».  
**Acceptance:** одразу після тесту видно 1–3 рекомендації.

### Таска 4.4 — UI рекомендацій на `/results`
**Що:** картки `RecommendedAction` під таблицею прогресу.  
**Acceptance:** є статистика + рекомендації; empty-state без спроб.

### Таска 4.5 — `persistRecommendations` + сесії «Авто»
**Що:** зберегти план (окрема таблиця або `task_sessions` «заплановано» + джерело Авто); схему узгодити з ментором.  
**Acceptance:** після фінішу/перерахунку в БД є заплановані «Авто»-сесії.

### Таска 4.6 — «Авто» на `/sessions`
**Що:** рядки Авто; Старт (модуль 3) і X (скасувати).  
**Acceptance:** Старт запускає тест; X прибирає план.

### Таска 4.7 — Живий `RecentResults`
**Що:** права колонка з реальних останніх %, не `PLACEHOLDER_RECENT_RESULTS`.  
**Acceptance:** після тестів сайдбар показує живі дані.

### Таска 4.8 (пізніше) — Призначення ментора
**Що:** створити заплановану сесію з джерелом «Ментор» (admin endpoint / інструмент).  
**Acceptance:** на `/sessions` рядок Ментор з Старт/X.

### Таска 4.9 (пізніше) — Граф тем (`theme_connections`)
**Що:** при високому % рекомендувати наступну тему за `vertex_start` → `vertex_finish`.  
**Acceptance:** тема A сильна → в рекомендаціях є тема B з ребра графа.

## Критичний шлях (demo ментору)

1. `.env.local` → БД з `quiz_tasks`.
2. Старт тесту за темою → 10 питань на екрані.
3. Відповіді → фініш з %.
4. `%` у «Результати за темами».
5. Сесія в «Навчальні сесії».
6. 1–2 рекомендації «що далі».

Імпорт можна показати окремо через `curl` + phpMyAdmin.
