# Онбординг розробника

Локальну TG-007 інтеграцію перевірено 2026-10-06: Telegram API підтвердив повідомлення та кнопку «Деталі», MySQL зберіг `delivered`; другий запуск не створює дубля, сесія й завдання незмінні. Докази та обмеження — в [інтеграції Telegram](telegram-integration.md#завершена-локальна-перевірка-tg-007--2026-10-06).

## 1. Про проєкт

nmt.in.ua — освітня платформа для підготовки до НМТ з математики. Вона охоплює діагностичне тестування, тести за темами, адаптивне тренування, задачник, підручник і навчальні матеріали, симулятор НМТ, результати й рекомендації, сценарії для учнів і викладачів, призначення завдань та консультації.

## 2. Технології

Проєкт використовує Next.js 16 App Router, React 19, TypeScript, MySQL (`mysql2`), CSS Modules, `next-intl` для локалізації, KaTeX для математичних формул і Motion для анімацій. Потрібні Node.js 20+ та npm. Перед змінами в коді Next.js прочитайте [AGENTS.md](../AGENTS.md): там є вказівки для встановленої версії.

## 3. Структура репозиторію

| Каталог | Призначення |
| --- | --- |
| `src/app/` | Маршрути, макети, сторінки, API-маршрути й рендеринг на рівні маршруту |
| `src/components/` | Повторно використовуваний UI: `dashboard/`, `testing/`, `welcome/`, `auth/` і `ui/` |
| `src/modules/` | Бізнес-логіка: зокрема `auth/`, `testing/`, `diagnostic/`, `recommendations/`, `sessions/`, `teacher-students/`, `consultations/` і `content-import/` |
| `src/lib/` | Спільна інфраструктура, зокрема утиліти для бази даних |
| `scripts/sql/` | SQL-скрипти схеми та міграцій |
| `content/` | Навчальні дані й контент |
| `messages/` | Ресурси локалізації |
| `docs/` | Документація проєкту |

## 4. Архітектурні правила

Маршрути `src/app/` та UI `src/components/` → `src/modules/*` → спільна база даних та інфраструктура.

Сторінки й UI-компоненти мають залишатися тонкими; бізнес-логіку розміщуйте в модулях. Для доступу до MySQL використовуйте наявний `getConnection()` із `src/lib/db/mysql.ts`. Не створюйте окремих пулів з'єднань у функціональних модулях. Для операцій форм і застосунку використовуйте Server Actions, а для міжсистемного доступу або API — HTTP API routes.

## 5. Локальний запуск

```bash
git clone https://github.com/tony-kobs/nmt.in.ua.git
cd nmt.in.ua
git checkout dev
npm install
cp .env.example .env.local
npm run dev
```

Відкрийте <http://localhost:3000>. Значення для локального середовища отримуйте від команди, а не з Git. Ніколи не комітьте `.env.local` і не додавайте продакшен-ключі чи облікові дані до документації. Назви змінних є в [`.env.example`](../.env.example), подробиці запуску — в [README.md](../README.md).

## 6. Робота з гілками

Звичайну роботу починайте від `dev`: створюйте окрему гілку `feature/*`, `fix/*` або `docs/*` і відкривайте PR у `dev`. Не пуште звичайні функціональні зміни безпосередньо в `main`. Шлях релізу: `dev` → `main`; злиття в `main` запускає продакшен-деплой.

```bash
git checkout dev
git pull origin dev
git checkout -b feature/example-task
```

## 7. Дизайн-система

Під час роботи з UI дотримуйтеся [`.cursor/rules/design-system.mdc`](../.cursor/rules/design-system.mdc). Верстайте за принципом mobile-first із брейкпоінтами 375 / 768 / 1240 / 1440 / 1920 і використовуйте CSS Modules. Беріть глобальні дизайн-токени з `src/app/globals.css`, не дублюючи їх локально. Для анімацій перевіряйте поведінку з `prefers-reduced-motion`.

## 8. Перевірка перед PR

```bash
npm test
npm run lint
npm run build
git diff --check
git status --short
```

Виправляйте помилки, переглядайте попередження й не додавайте до PR сторонні зміни або секрети. Стверджуйте, що перевірка пройшла, лише якщо справді її запускали.

## 10. Перші 30 хвилин

1. Прочитайте цей путівник і `AGENTS.md`; якщо працюватимете з UI — також файл дизайн-системи.
2. Клонуйте репозиторій і перейдіть на `dev`.
3. Отримайте від команди локальні значення змінних і налаштуйте `.env.local`.
4. Встановіть залежності, запустіть застосунок і виконайте `npm test` до змін у коді.
5. Оберіть невелике завдання, створіть окрему гілку та виконайте лише його.
6. Запустіть тести, lint і build, перегляньте diff та відкрийте PR у `dev`.

## TG-008 — запуск сповіщень

Реалізовано захищений POST trigger і GitHub Actions schedule кожні 5 хвилин + workflow_dispatch на main для основного хостингу ukraine.com.ua. Потрібен окремий TELEGRAM_NOTIFICATIONS_TRIGGER_SECRET у runtime та GitHub Secrets, міграція 037 і чинні налаштування Telegram. Порядок активації, зупинки й обмеження — у [Telegram integration](telegram-integration.md#tg-008--автоматичний-запуск-сповіщень). Production scheduler ще не запускався; TG-009 заплановано.
