# Лідерборд nmt.in.ua — продуктова пропозиція

Оновлено: 7 жовтня 2026. Статус: **до узгодження з PM** (разом із таскою **8.4 «Марафон»**).

Пов’язані рішення PM (блокери марафону): тривалість (7 / 14 / 30 днів), щоденна порція (тест за темою / N задач / симулятор / мікс), канал (кабінет / Telegram / обидва), спосіб реєстрації (кнопка / бот / запрошення викладача / оплата).

---

## 1. Принцип

**Не робити глобальний топ усіх учнів платформи.** Це слабко мотивує слабших, створює токсичність і конфліктує з приватністю (особливо для шкільних груп).

**Робити контекстні лідерборди** — рейтинг лише в межах змагання, де учень сам (або через викладача) погодився брати участь:

| Контекст | Хто бачить | Навіщо |
| --- | --- | --- |
| **Марафон** (основний v1) | Учасники цього марафону | Щоденна мотивація, streak, «день закрито» |
| **Група викладача** (v1.5) | Учні однієї групи + викладач | Здорове змагання в класі, без всієї України |
| **Особистий прогрес** | Лише учень | Не лідерборд, а «ти vs ти» + досягнення |

Досягнення (`/account`, зараз заглушка) — **окремий шар**: бейджі за віхи (перший симулятор, 7 днів підряд у марафоні). Вони можуть давати **бонусні очки** у марафоні, але не замінюють таблицю місць.

---

## 2. Учень

### Що бачить

1. **Сторінка марафону** (майбутній маршрут, напр. `/marathon` або `/marathon/[id]`):
   - реєстрація / «Сьогоднішня порція» / прогрес «день 5 з 14»;
   - блок **«Таблиця марафону»**: місце, ім’я (або нік), streak, очки за сьогодні / загалом;
   - фільтр: **сьогодні** / **загалом** (два режими метрики — узгодити з PM).
2. **Не показувати** учням рейтинг поза їхнім марафоном.
3. **Досягнення** на `/account`: галерея бейджів; клік — що зробити далі (лінк на тему / марафон / симулятор).

### Поведінка метрик (пропозиція до PM)

- **День зараховано**: щоденна порція виконана до дедлайну (північ Києва або 24 год від старту дня — вирішити).
- **Пропуск**: день не зараховано; streak обнуляється (або «заморозка» 1 раз на марафон — опційно).
- **Очки** (проста формула v1): +100 за закритий день; +бонус за % порції; +малі бонуси з досягнень. Без pay-to-win.

### Чому так

Учень у марафоні вже в контексті «граю 14 днів» — лідерборд підсилює звичку, а не порівнює з невідомими з інших міст.

---

## 3. Викладач

### Що бачить

1. **У «Мої учні» / група**: хто в якому марафоні, **хто сьогодні не зайшов** (пріоритетніше за «хто 1-е місце»).
2. **Таблиця групи** (як `/results`, worst-first за замовчуванням):
   - колонки: учень, streak, дні закрито / пропущено, місце в марафоні (якщо один спільний марафон класу);
   - клік → картка учня (вже є `/students/[id]`).
3. **Запрошення в марафон** (якщо PM обере «запрошення викладача»): код / галочки учнів, як у `/assign`.

### Чого не робити

- Окремий «топ України» для викладача.
- Публічне ім’я учня в лідерборді без згоди (opt-in на рівні марафону або групи).

### Чому так

Викладачу потрібен **моніторинг залучення** (хто відстав), узгоджений із уже існуючими `/results` і `/sessions`, а не esports-рейтинг.

---

## 4. Адмін

### Що бачить

1. **Каталог марафонів** (CRUD після рішень PM): назва, тривалість, правило денної порції, дати старту, активний / архів.
2. **Прив’язка лідерборду**: один марафон → один `leaderboard_id` (тип `marathon`).
3. **Модерація**: приховати запис з таблиці, зняти учасника з марафону, не чіпати глобальний профіль без причини.
4. **Без** окремої адмінки «весь сайт — один рейтинг».

### Технічний мінімум (після рішень PM)

- Таблиці: `marathons`, `marathon_participants`, `marathon_days`, `marathon_day_completions` (статус: done / skipped / pending).
- `leaderboards` + `leaderboard_entries` (універсальні для марафону й майбутньої групи).
- Перерахунок місць: job після закриття дня або on-write з кешем `rank` (до ~500 учасників на марафон — достатньо синхронно).

### Чому так

Адмін конфігурує **продуктові кампанії** (марафон), а не керує соціальною мережею.

---

## 5. Зв’язок: марафон → лідерборд → досягнення

```text
[PM: правила марафону]
        ↓
marathon_instance + daily_portion
        ↓
completion events → score + streak
        ↓
leaderboard_entries (scope = marathon_id)
        ↓
UI: таблиця місць у марафоні
        ↓
achievement_rules (напр. streak ≥ 7) → user_achievements на /account
```

Лідерборд **не обчислює** досягнення сам; модуль досягнень слухає події (день закрито, N-й симулятор тощо).

## 6. UI / маршрути (етапи)

| Етап | Що | Залежність |
| --- | --- | --- |
| **0** | ТЗ марафону + mockup (таска 8.4) | PM |
| **1** | Доменні таблиці + API місць у марафоні | Після PM |
| **2** | Сторінка марафону з таблицею (учень) | Етап 1 |
| **3** | Панель викладача (група + «хто пропустив сьогодні») | Етап 2 |
| **4** | Досягнення (замість заглушки `/account`) | Можна паралельно з 3 |
| **5** | Telegram-нагадування | Окреме рішення PM по каналу |

Поточний кабінет уже має **divisions за контекстом**: `/results`, `/sessions` (пагінація з 768px, свайпер на мобілці) — марафон логічно лягає як новий пункт меню, не переробка глобального `/`.

## 7. Відкриті питання до PM (додати до картки 8.4)

1. Чи показувати в таблиці **повне ім’я** чи нік / «Учень №12»?
2. Чи можна **вийти з марафону** і чи лишається історія в лідерборді?
3. Один активний марафон на учня чи кілька?
4. Чи потрібен **лідерборд без марафону** (лише група викладача) у v1?
5. Порівняння «краще ніж 80%» з EPIC 5 — **закрити** на користь контекстних лідербордів?

---

## 8. Що вже є в коді (не плутати з лідербордом)

- `/results`, `/sessions` — аналітика, не змагання.
- `compareByWorstScore` у викладача — для підтримки, не рейтинг.
- Заглушки «Досягнення» / «Час навчання» на `/account`.
- **`/leaderboard`** (гілка `leaderboard`): таблиця учасників **активного марафону** (`marathons` + `marathon_participants`), очки з завершених `task_sessions` у вікні дат; кнопка «Приєднатися». Пілотний марафон сідається lazy-схемою. Щоденні порції / streak — наступний етап після PM.
- Пагінація та мобільний свайпер для `/results` і `/sessions` — окремо, не загубились.
